# 削除検知と単一コメント表示の設計

## 方針

新着コメントの取得と、単一コメントを表示する直前の削除確認は別責務にする。

```text
新着コメント     : YouTubeのストリーム接続で低遅延に受信する
削除・撤回の確認 : 単一コメント表示操作の直前に現在の一覧を取得する
```

削除だけを監視する固定間隔のポーリングは行わない。表示中コメントが後から削除された場合も、自動では非表示にしない。次の表示操作で最新状態を確認する、というトレードオフを採用する。

## 新着コメント

- `liveChatMessages.streamList` 相当のストリーム接続を維持する。
- コメントIDが未受信なら履歴へ追加する。
- 履歴とは別に、未表示コメントIDだけを `Next` キューへ積む。
- 表示済み・削除済み・取り消し済みのIDは `Next` キューから除外する。

履歴は管理画面用の記録、`Next` キューは「次に1件表示する候補」のための状態であり、同じ配列として扱わない。

## 単一コメント表示時の検証

単一コメントを表示する操作（個別表示または「次を表示」）は直列化する。各操作で以下を実施する。

1. `liveChatMessages.list` を `maxResults: 200`、`pageToken` なしで取得する。
2. 明示的な `tombstone` と撤回プレースホルダを既存履歴へ反映する。
3. 表示候補が通常コメントとして一覧に存在するか確認する。
4. 取得中に配信が停止・切替されていないことを再確認する。
5. 有効なら1件表示し、候補IDを `Next` キューから取り除く。
6. 削除跡・撤回・一覧不在なら表示せず、次候補を試す。

YouTube APIは `maxResults` に200〜2000を要求する。想定配信は2時間で約100コメントのため、200件の一覧で候補を確認できる前提にする。

### 200件上限時

応答が200件ちょうどの場合、一覧に無いことだけでは削除を確定しない。取得範囲外に出た可能性があるためである。

ただし安全側に倒し、一覧で確認できない候補は単一コメント表示しない。API応答の失敗時や、取得中に配信が切り替わった場合も候補を消費せず、現在の表示を維持する。

## 削除状態

| 観測内容 | 処理 |
| --- | --- |
| 同じIDの `tombstone` | ただちに削除済みへ更新 |
| 撤回プレースホルダ | 元コメントを投稿者取り消しへ更新 |
| 200件未満の一覧で候補IDが不在 | 削除済みへ更新し、表示しない |
| 200件上限の一覧で候補IDが不在 | 未検証として表示しない。削除済みには確定しない |

`tombstone` は削除時の即時通知ではない。そのため、保証できるのは「単一コメント表示操作の開始時に取得できた最新一覧に基づいて、削除・未検証候補を表示しない」ことまでである。

## 意図的な制限事項

- 表示中のコメントがYouTube上で削除されても、次の表示操作または手動非表示までは残る。
- 一覧取得と表示の間に削除された場合を原子的に防ぐAPIはない。
- YouTube側で痕跡が残らない削除は判定できない。
